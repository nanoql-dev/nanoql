# nanoql

nanoql is a stateless quantitative finance library for .NET. Every model and pricer is a plain function of its
inputs: there are no observers, lazy objects or global evaluation date, and market conventions are data, not code.

## Install

- **.NET:** `dotnet add package NanoQL`, and `NanoQL.Extensions` for the conventions' XML format and the instruments
  and models beyond the core.
- **Python:** `pip install nanoql`.
- **C and C++:** `nanoql-2.2-<platform>-c-api` on [the release](https://github.com/nanoql-dev/nanoql/releases/tag/v2.2):
  the C and C++ headers, the library, its CMake package and the notices ([C++](docs/cpp.md)).
- **Excel:** `nanoql-excel-2.2-win-x64.zip` on the release: the add-ins and five example workbooks.

nanoql's first public release is 2.0, the whole library rather than a preview. Its versions have two parts: a minor
release adds, and nothing stable is removed until it has been deprecated for at least two releases and a year. The
experimental API may change in any release, and its released names are never reused. Each release's changes are in
[CHANGELOG.md](CHANGELOG.md).

## Principles

- **Stateless in structure.** Inputs are immutable records; models, calibration and pricers are static functions.
  The same inputs always give the same outputs, and calls are safe to run in parallel.
- **Conventions as data.** Calendars, day counts, currencies, indexes and the instrument builders' defaults are XML
  records that a desk can read, override and version, so changing one is a data change, not a code change (see
  [docs/conventions.md](docs/conventions.md)).
- **Checked against its sources.** The core's results are checked against [QuantLib](https://www.quantlib.org/) 1.44,
  using test vectors generated by QuantLib's Python package and by QuantLib built from source; the extensions ported
  from QLNet are checked against QLNet 1.13.2. The vectors are committed to this repository, and what they cover is
  under [Validation](#validation).
- **Traceable to its sources.** Each ported file records the library, path and release it was ported from.
- **Python, C and C++ without .NET.** One C interface over nanoql compiled with Native AOT: Python's wheels hold it,
  so `pip install nanoql` needs no .NET runtime, and the C archive, with its C++ header and CMake package, serves
  C++ and any language that calls C.

## Platforms

Windows x64 is the validated platform. The .NET library on Linux and macOS, and the native library under C and Python
on Linux x64, are supported: built and tested in every release run, their known differences listed in each release's
notes. The native library ships for Windows x64 and Linux x64; Windows Arm64, Linux Arm64 and macOS on Apple silicon
follow in later releases.
