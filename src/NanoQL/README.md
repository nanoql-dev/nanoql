# NanoQL

Quantitative finance for .NET, stateless by design: calendars, curves, instruments, pricing engines and models, each a
plain function of its inputs, with market conventions as data. There are no observers, lazy objects or global
evaluation date, so the same inputs always give the same results, on any thread.

```shell
dotnet add package NanoQL
```

It targets .NET 10. The conventions' XML format and the instruments and models beyond the core are in a second
package, [NanoQL.Extensions](https://www.nuget.org/packages/NanoQL.Extensions).

## A first swap

A five-year SOFR swap on a flat curve. The evaluation date goes in an `EvaluationContext`, the curve and the swap are
values, and the engine is a static function of them:

```csharp
using NanoQL;
using NanoQL.Indexes;
using NanoQL.Instruments;
using NanoQL.PricingEngines;
using NanoQL.TermStructures;
using NanoQL.Time;

var today = new Date(15, Month.October, 2026);
var context = new EvaluationContext { EvaluationDate = today };
var curve = new FlatForward(today, 0.036, new Actual365Fixed());

var swap = new MakeOIS(new Period(5, TimeUnit.Years), new Sofr(curve))
    .WithFixedRate(0.036).WithNominal(10e6)
    .ToOvernightIndexedSwap(context);

var result = DiscountingSwapEngine.Calculate(swap, context, curve);
Console.WriteLine($"NPV {result.NPV:N2}, fair rate {result.FairRate:P4}");
```

## How it is checked

The core's results are checked against QuantLib 1.44, using test vectors generated by QuantLib's Python package and
by QuantLib built from source; the extensions ported from QLNet are checked against QLNet 1.13.2. What the checks
cover, per module, is on [the validation page](https://nanoql.org/validation/).
