# NanoQL.Excel

The runtime of nanoql's Excel add-in: handles, conversions, errors and settings for the worksheet functions
nanoql-bind generates.

Nobody installs it by hand. nanoql's own add-ins, `nanoql64.xll` and `nanoql-experimental64.xll`, carry it inside each
`.xll`, in the release's `nanoql-excel-2.3-win-x64.zip` on
[GitHub](https://github.com/nanoql-dev/nanoql/releases). An add-in of your own, your worksheet functions beside
nanoql's, is built by the tool, [NanoQL.Bind](https://www.nuget.org/packages/NanoQL.Bind), which writes its project
with a reference to this package and restores it from NuGet. Given your assembly's build output, holding nanoql's two
assemblies beside it ([NanoQL.Bind](https://www.nuget.org/packages/NanoQL.Bind) says how):

```shell
dotnet tool install --global NanoQL.Bind
nanoql-bind excel build --out acme-addin \
  --assembly nql=bin/NanoQL.dll --assembly nql=bin/NanoQL.Extensions.dll --assembly acme=bin/Acme.dll
```

The add-ins need 64-bit Excel for Microsoft 365 on Windows x64 and the .NET 10 Desktop Runtime, x64. The functions,
their names and how a workbook calls them are in [the Excel guide](https://nanoql.org/docs/excel.html).

## How it is checked

The core's results are checked against QuantLib 1.44, using test vectors generated by QuantLib's Python package and
by QuantLib built from source; the extensions ported from QLNet are checked against QLNet 1.13.2. What the checks
cover, per module, is on [the validation page](https://nanoql.org/validation/).
