# NanoQL.Extensions

nanoql's extensions: market conventions as XML data (calendars, day counts, indexes and the instruments' defaults),
and instruments and models beyond the core. It builds on [NanoQL](https://www.nuget.org/packages/NanoQL).

```shell
dotnet add package NanoQL.Extensions
```

## Conventions as data

Every preset nanoql ships is a record a desk can read, override and version. A file of the desk's own records is
layered over the presets, and a misspelt name or a bad value is refused when the file is read:

```csharp
using NanoQL;
using NanoQL.Extensions.Conventions;
using NanoQL.Time;

// TARGET with an extra holiday, over the shipped presets
File.WriteAllText("desk.xml", """
    <Conventions xmlns="https://nanoql.org/schemas/conventions">
      <Calendar name="TARGET" base="TARGET">
        <AddedHoliday>2026-12-24</AddedHoliday>
      </Calendar>
    </Conventions>
    """);
ConventionSet desk = ConventionSet.QuantLib.With(ConventionsXml.Read("desk.xml"));
Date eve = new(24, Month.December, 2026);
Console.WriteLine(ConventionSet.QuantLib.Calendar("TARGET").IsBusinessDay(eve)); // True: a business day in the presets
Console.WriteLine(desk.Calendar("TARGET").IsBusinessDay(eve));                   // False: the desk's holiday
```

`ConventionProvider.Default = desk;` makes the desk's records the defaults of every object built after it. The
format and the shipped records are in [the conventions guide](https://nanoql.org/docs/conventions.html), and the
schema at [nanoql.org/schemas/conventions](https://nanoql.org/schemas/conventions/).

## How it is checked

The core's results are checked against QuantLib 1.44, using test vectors generated by QuantLib's Python package and
by QuantLib built from source; the extensions ported from QLNet are checked against QLNet 1.13.2. What the checks
cover, per module, is on [the validation page](https://nanoql.org/validation/).
