# nanoql for Python

nanoql for Python: quantitative finance, stateless by design, through nanoql's C interface. Calendars, curves,
instruments, pricing engines and models are each a plain function of their inputs, with market conventions as data,
and the same inputs always give the same results.

```shell
pip install nanoql
```

One wheel per platform, for every Python from 3.11, with NumPy 1.26 or later and nothing compiled on install: Windows
x64 and Linux x64 (`manylinux_2_28`, glibc 2.28 or later); Windows Arm64, Linux Arm64 and macOS on Apple silicon follow
in later releases. The wheel holds nanoql's native library, so no .NET runtime is needed.

## A first swap

A five-year SOFR swap on a flat curve:

```python
import datetime
from nanoql import ConventionSet, DiscountingSwapEngine, EvaluationContext, FlatForward, MakeOIS, Period, TimeUnit

today = datetime.date(2026, 10, 15)
context = EvaluationContext(today)
qs = ConventionSet.quant_lib()
curve = FlatForward(today, 0.036, qs.day_counter("Actual365Fixed"))

swap = (MakeOIS(Period(5, TimeUnit.Years), qs.overnight_index("Sofr", curve))
        .with_fixed_rate(0.036).with_nominal(10e6)
        .to_overnight_indexed_swap(context))

result = DiscountingSwapEngine.calculate(swap, context, curve)
print(f"NPV {result.npv:,.2f}, fair rate {result.fair_rate:.4%}")
```

Names follow PEP 8 (`curve.discount(5.0)`, `swap.fixed_rate`), a getter is a property, and an object's handle is
released when Python collects it, or at once by `close()` or a `with` block. `import nanoql.experimental` opts in to
the experimental API. The rules are in [the bindings guide](https://nanoql.org/docs/bindings.html).

[A notebook](https://github.com/nanoql-dev/nanoql/blob/main/docs/notebooks/first-steps.ipynb) takes this swap
further, to bootstrapped curves, €STR discounting and Euribor forecasting, a SABR smile, an American put and a CDS; it [runs in Google Colab](https://colab.research.google.com/github/nanoql-dev/nanoql/blob/main/docs/notebooks/first-steps.ipynb) with nothing to
install.

## How it is checked

The core's results are checked against QuantLib 1.44, using test vectors generated by QuantLib's Python package and
by QuantLib built from source; the extensions ported from QLNet are checked against QLNet 1.13.2. What the checks
cover, per module, is on [the validation page](https://nanoql.org/validation/).
